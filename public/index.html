What TWINTICKER is

TWINTICKER is an AI agent on Binance Agent OS that watches Ondo-tokenized US stocks on BNB Chain and compares them to the underlying US equity in real time. When the on-chain price drifts away from the equity, TWINTICKER names the cause, scores the edge, and — with your own Agentic Wallet — can swap into the mispriced side.

It runs three small agents: a Reader that pulls live on-chain data and the underlying equity price from the official binance-tokenized-securities-info REST API, an Analyzer that applies the Ondo sharesMultiplier and emits a deterministic verdict (FAIR_VALUE / UNDERVALUED / OVERVALUED / HALTED), and a Scanner that runs the whole pipeline across the full Ondo universe and ranks by absolute divergence. The LLM is called once, after the verdict, to write a one-paragraph rationale from numbers it didn't generate.

Built as a Model Context Protocol (MCP) server, the same agent is reachable from Claude Code, Codex, Cursor, Windsurf, and any other MCP-compatible client. Execution is opt-in and uses your own Agentic Wallet — the hosted site never holds keys.

The problem it tackles

Ondo's Global Markets tokens on BNB Chain are designed to track the underlying US equity 1:1. In practice the link breaks in four ways that an unwary trader misses.

  • Stale oracle after the bell. The US market closes at 4 PM ET. For the next 16+ hours, the on-chain price is fixed at the last close while the underlying equity is in after-hours / pre-market trading. The "premium" you see is just a clock skew, not an edge.
  • Corporate actions that don't propagate on-chain. Earnings halts, dividend declarations, splits, M&A — the tokenized wrapper may not refresh at the same instant. The Binance reasonCode field carries the truth; most dashboards ignore it.
  • Multiplier drift. Ondo's sharesMultiplier is meant to absorb splits and dividends. If the on-chain value diverges from the reference price by more than a few bps after the multiplier is applied, something is wrong.
  • Hand-wave rationales from black-box agents. Most "AI agents" in this space give you a number with no provenance. TWINTICKER shows every input — the contract address, the observed on-chain price, the reference equity price, the multiplier, the raw divergence in basis points — so you can audit the verdict yourself.

Use cases

1. End-of-day audit for RWA holders

If you hold NVDAon, AAPLon, TSLAon — or any of the 444 Ondo Global Markets tokens — and want to know right now whether the wrapper is tracking the underlying, the twinticker_scan tool gives you the verdict in one call.

2. Trading-agent signal feed

Point any MCP-capable trading agent at https://twinticker.vercel.app/mcp and it gets a clean UNDERVALUED / OVERVALUED / HALTED signal on every Ondo token, refreshed every few seconds.

3. Corporate-action monitor

Around earnings, splits, dividends, and M&A announcements, the marketStatus.reasonCode from Binance flips to EARNINGS_HALT, SPLIT_HALT, DIVIDEND_HALT, or MAINTENANCE. TWINTICKER surfaces this in every verdict and refuses to recommend action during a halt.

4. Liquidity-provider / market-maker backstop

If you quote two-sided liquidity on PancakeSwap for one of these tokens, you need to know when the on-chain price has drifted from fair value so you can widen your quote. A scan_all call gives you the full ranked list in one round trip.

FAQ

Is this live trading?

The hosted site is read-only: scan, scan-all, and a structured verdict card. No keys, no signing, no broadcast. To actually swap, you install the stdio MCP shim locally and pair your own Agentic Wallet — the swap is then confirmed in the Binance app on your phone before broadcast.

Where does the data come from?

On-chain price and US equity price both come from the official binance-tokenized-securities-info REST API — the same data source that powers the on-chain view in the Binance app. The sharesMultiplier and reasonCode are read from the same response, so the verdict accounts for corporate actions in one place.

Is the verdict from the LLM or from math?

The verdict is deterministic. The 20-line function that decides FAIR_VALUE / UNDERVALUED / OVERVALUED / HALTED runs the same on the same input. The LLM is called once, after the verdict, to write a one-paragraph rationale from numbers it didn't generate. Two scans over the same data return the same verdict and a near-identical rationale.

Can an LLM talk its way past the verdict?

No. The LLM is called in read-only mode (no tool access). It returns text that the page renders below the deterministic verdict. The verdict itself is computed before the LLM is invoked. There is no code path by which the LLM's output changes the recommendation.

What does HALTED mean?

Binance's reasonCode is one of EARNINGS_HALT, SPLIT_HALT, DIVIDEND_HALT, MAINTENANCE, or MERGER_HALT. The on-chain wrapper is in a known non-trading state. TWINTICKER surfaces this and refuses to recommend action until the state clears.

How is the swap size capped?

The executor hard-caps each swap at 5 USDT (the BAW_MAX_SWAP_USDT env var). Both the Vercel-side bridge and the local baw CLI independently enforce this. To raise the cap, edit the constant in src/agents/executor.js.

Does the site ever see my private key?

No. The hosted Vercel deployment has no wallet code paths. Even with the optional VPS bridge set up, the key is held by the baw CLI on your own machine, never transmitted to Vercel or to the browser. The baw CLI calls Binance directly.

What about the off-hours "drift" I see on every scan?

When the US market is closed, the on-chain wrapper stays at the last close. The underlying equity is in after-hours / pre-market. The verdict is still FAIR_VALUE if the divergence is small, because the wrapper is behaving as designed. TWINTICKER reports the raw divergence either way; the verdict just doesn't fire on it. The Binance offhours field is included in every response for transparency.

What's the latency?

A single scan against the live API: ~1.2 s end-to-end (network to Binance + verdict + LLM rationale). A full scan_all across the 444 tokens: ~10 s on cold start, then memoized. The MCP handshake completes in under 300 ms against the official SDK.

Can I run this myself?

Yes. git clone https://github.com/ruzkypazzy/twinticker, npm install, npm start — it runs locally on Node 22 with no Vercel, no cloud account, no API keys. To enable live execution, install baw, pair your wallet, set BAW_ENABLED=true. See the README for the four setup paths.

How it works

TWINTICKER runs three agents: a Reader that pulls on-chain token data via binance-tokenized-securities-info and the underlying US equity price from a free public feed; an Analyzer that computes the divergence in basis points, applies the Ondo multiplier, and produces a verdict (FAIR_VALUE / UNDERVALUED / OVERVALUED / HALTED); and a Scanner that runs the whole pipeline across the full Ondo universe and ranks by absolute divergence. The MCP server exposes both twinticker_scan and twinticker_scan_all to any MCP-compatible agent — Claude Code, Codex, Cursor, ChatGPT. Built for the Binance Agent OS Mini Hackathon.
